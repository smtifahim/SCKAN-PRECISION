# SCKAN ↔ PRECISION Explorer (Web UI)

A static, client-side HTML/CSS/JS app that visualizes how SCKAN's anonymous
neural connectivity populations relate to PRECISION's molecularly-defined
DRG/TG cell types, using the JSON exports in [`resource/json/`](../resource/json)
(generated by [`script/npo-query.py`](../script/npo-query.py)).

## Running it

**Hosted:** <https://smtifahim.github.io/SCKAN-PRECISION/> (GitHub Pages, served
from the repository root of the `main` branch; the root `index.html` forwards
to `web/index.html`).

**Locally:** the app loads its data with `fetch()`, so it must be served over
HTTP (not opened directly as a `file://` URL), **from the repository root**, so
that both `web/` and `resource/` are reachable:

```bash
# from the repository root
python3 -m http.server 8000
```

Then open <http://localhost:8000/web/index.html>.

Any static file server works, as long as it's started from the repo root
(not from inside `web/`) - `web/js/data/config.js` resolves the JSON paths as
`../resource/json/...` relative to `web/index.html`.

## Structure

```
web/
  index.html          Page shell: header, view tabs, filter bar, diagram/table panels
  css/                 base.css (layout/typography), filters.css, diagram.css, table.css
  js/
    data/              JSON loading + cross-referenced data models (shared end-organ/
                       partial-order indexing in sharedPopulationModel.js) + IRI→CURIE→URL rules
    filters/           Autocomplete widget, fiber-type tree selector, cascading-filter logic
                       (cascade.js for View A, cascadeB.js for View B)
    diagram/           Graphviz DOT generation (diagram + legend), SVG rendering/click
                       wiring, evidence-panel rendering (legend.js / legendB.js), PNG export
    views/             View (A)/(B) orchestration, the alternative table views, Excel
                       export, resizable-panel helper
    shared/            HTML-rendering helpers (IRI links, escaping, DOI/citation formatting)
    app.js             Entry point: tab switching, bootstraps both views
  vendor/graphviz/      Vendored @hpcc-js/wasm-graphviz (offline, no CDN/network dependency)
```

## View (A): DRG Afferents of the Kidney

Lists every SCKAN DRG/TG population terminating in the kidney
([`drg-end-organs.json`](../resource/json/drg-end-organs.json)), renders each
one's route as a Graphviz partial-order diagram
([`drg-partial-order.json`](../resource/json/drg-partial-order.json)), and
draws dotted RDF-star-style edges from each soma node to its candidate
PRECISION cell types ([`drg-organ-innervation.json`](../resource/json/drg-organ-innervation.json)).

- **Filters** (End Organ, Species, Gene, Axon/Fiber Type, Circuit Role) cascade:
  picking one narrows the option lists/available values in the others, based
  on what's actually present in the data (not static lists).
- **Axon/Fiber Type** uses [`fiber-type-hierarchy.json`](../resource/json/fiber-type-hierarchy.json):
  selecting a parent fiber type matches it and every descendant.
- **Species/Gene/End-Organ** autocomplete also matches synonyms from
  `synonyms-species.json`, `synonyms-gene.json`, `synonyms-organs.json`, but
  the suggestion list itself is always restricted to IRIs that actually occur
  in the cascade-filtered dataset.
- The **legend** above the diagram is itself a small Graphviz diagram
  ([`diagram/legendDiagram.js`](js/diagram/legendDiagram.js)), reusing the
  exact node/edge styles from the main diagram, so its text sits inside each
  shape and it composes losslessly into the PNG export.
- Click a dotted edge to see the matched evidence (species, marker gene,
  circuit role, end organ, citation with a clickable DOI link) plus candidate
  phenotypes the cell type suggests for that SCKAN population, in the
  resizable right-hand evidence panel (drag its left edge; clamped between
  260px and 35% of the window width).
- The **SCKAN Populations** panel below the diagram is its own scrollable
  card (never grows the page) listing each population's curie (linked to
  SCKAN Explorer), preferred label, and - when present - its candidate count
  plus the matched cell-type labels.
- A couple of composer-drafted kidney populations need a distinguishing curie
  prefix on SCKAN Explorer's side; see `CURIE_OVERRIDES` in
  [`data/curie.js`](js/data/curie.js).
- Every node is clickable: SCKAN populations open in
  [SCKAN Explorer](https://sckan-explorer.netlify.app), PRECISION cell types
  open in [NervoSensus](https://nervosensus.netlify.app), everything else
  opens its own raw IRI.
- **Export PNG** rasterizes the legend + diagram + a simple curie/label
  caption for the selected population into one downloadable PNG.
- Switch to the **Table** view for a flat, filterable grid (with Threshold /
  Neurotransmitter Phenotype and Neural Circuit Membership columns) and an
  **Export to Excel** button (downloads an HTML-table-based `.xls` file that
  Excel opens natively, hyperlinks included).
- Toggle diagram layout (left-to-right / top-to-bottom), and use
  **Reset filters** to clear all selections.

## View (B): Candidate PRECISION Cell Type Mapping

Structurally identical to View (A) - same cascading filters, partial-order
diagram with dotted candidate-match edges, population caption table, evidence
panel and alternative table view - but reads the mapping stored via
`ilxtr:hasCandidateCellType` instead of `ilxtr:isCompatibleWith`
([`candidate-mapping.json`](../resource/json/candidate-mapping.json), see
[`resource/sparql/candidate-mapping.rq`](../resource/sparql/candidate-mapping.rq)
for the exact RDF-star shape). It covers a different set of SCKAN DRG/TG
populations than View (A) (generic "pain1"/"pain2" populations scoped to
organs like skin, muscle, membrane, trunk, mouth, etc. - not kidney-specific),
so its default End Organ is "skin of body" rather than "kidney".

- **Filters**: End Organ, Species, Gene Phenotype, Axon/Fiber Type - no
  Circuit Role filter, since that field has no label data in this dataset
  (the underlying query still requires `ilxtr:hasCircuitRole` to exist on the
  mapping, it just isn't projected with a label).
- The dotted candidate-match edges carry required soma/origin + axon-type
  evidence, plus whichever optional evidence is present on a given match
  (species, gene phenotype, functional/threshold/neurotransmitter phenotype,
  neural circuit membership) - shown directly in the evidence panel's table
  rather than as a separate "suggested phenotypes" section (unlike View A,
  these fields are the match's own stored evidence, not an enrichment idea).
- The **Table** view's columns mirror the evidence fields above (no Circuit
  Role or Citation columns, since View B's data has neither).
- Everything else - node styling/colors, clickable SCKAN Explorer/NervoSensus
  links, the "Other cell type matches" list with click-to-promote, PNG/Excel
  export, layout toggle, resizable panels - is identical to View (A).
